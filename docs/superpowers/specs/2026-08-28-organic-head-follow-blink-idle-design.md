# 猫咪桌宠自然头部跟随、眨眼与闲置歪头设计规格

日期：2026-08-28  
状态：待用户审阅批准  
适用基线：Windows 六帧逐像素 Alpha 桌宠版  

## 1. 目标

在不破坏现有三组六帧点击动作、拖动、滚轮缩放、右键菜单、置顶、气泡和单 EXE 交付的前提下，新增三项环境动作：

1. 猫的眼睛、面部、头部和颈部自然跟随鼠标位置。
2. 以正常、略带随机的节奏眨眼。
3. 长时间闲置时，低概率向屏幕左或屏幕右歪头，再自然回正。

质量目标不是“头图围绕一个点旋转”，而是头颈两侧发生不同程度的压缩、拉伸和遮挡变化。最终观感必须像有柔软颈部和毛发连接的猫，而不是皮影、纸片或贴图转轴。

## 2. 非目标

首版明确不做：

- 不接入完整 Live2D、Inochi2D、Qt、OpenGL 或新的 GPU 运行时。
- 不做通用骨骼、IK、布料、毛发物理、摄像头人脸追踪。
- 不用全局鼠标钩子，只读取系统鼠标坐标。
- 不把整颗头简单旋转，也不通过整图 Alpha 交叉淡化伪装连续形变。
- 不一次性生产方向、眨眼、歪头的全部笛卡尔积组合。
- 不改变三组点击动作“每组恰好六帧”的合同。
- 不覆盖当前稳定 EXE；新版本使用独立名称交付。

## 3. 已验证基线与研究依据

### 3.1 当前素材和程序基线

- 当前中性姿态基准锁定为 `assets/keyframes/jump/00.png`；它与 `assets/pet/idle.png` 字节一致。
- 基准 SHA-256：`48f710b9811ebf6edc60764bc7a52fd1af4274a761589677df365450d8a2fec7`。
- 基准画布为 `512×768 RGBA`，角色可见包围盒约为 `(32,212)-(480,736)`。
- 基准图约有 9,085 个半透明抗锯齿像素。这些 Alpha 必须保留，不能二值化；逐像素 Alpha 窗口能够正确显示它们。
- 原始照片 `cat-original.png` 为 `631×1420 RGB` 白底，只用作脸、眼睛、花纹和毛发身份参考，不用作当前几何底图。
- 现有点击动作是三组完整画布，每组六帧、每帧 `512×768 RGBA`；新环境动作必须与它们分开加载和仲裁。
- 当前渲染器使用 Win32 `UpdateLayeredWindow`，应继续保留。

### 3.2 成熟方案提供的启发

- Live2D Cubism 官方示例把头、身体和眼球拆成不同参数，并使用带速度、加速度和减速的目标点，而不是让所有部位同步贴着鼠标移动：
  - [Cubism Web Samples 的头部、身体、眼球参数](https://github.com/Live2D/CubismWebSamples/blob/develop/Samples/TypeScript/Demo/src/lappmodel.ts)
  - [CubismTargetPoint 平滑目标算法](https://github.com/Live2D/CubismWebFramework/blob/develop/src/math/cubismtargetpoint.ts)
- Cubism 的眨眼采用随机等待以及闭合、停留、睁开三个阶段，可作为本项目的节奏参考：
  - [CubismEyeBlink](https://github.com/Live2D/CubismWebFramework/blob/develop/src/effect/cubismeyeblink.ts)
- Inochi2D 证明了“分层图片 + 网格变形器 + 参数关键点插值”适合不对称的头颈软形变：
  - [Inochi2D](https://github.com/Inochi2D/inochi2d)
  - [Inochi Creator](https://github.com/Inochi2D/inochi-creator)
- Mouse Tracker for Cubism 证明鼠标坐标、自动眨眼、随机闲置动作可以由同一个轻量状态协调器管理，但其 Linux/X11 和 Cubism SDK 依赖不适合直接复用：
  - [Mouse Tracker for Cubism](https://github.com/adrianiainlam/mouse-tracker-for-cubism)

### 3.3 路线决定

采用：

> 离线网格绑定与关键姿态烘焙 + 运行时轻量分层合成 + 单一动画协调器。

离线工具负责真正的网格拉伸、两侧不对称压缩、遮挡和毛发接缝；运行时只读取预烘焙透明状态图，移动受眼罩约束的眼球，切换眼睑和歪头状态，并继续通过 Win32 逐像素 Alpha 显示。

这条路线保留当前轻量程序和打包方式，同时避开商业许可、GPU 透明窗口重构和额外运行时依赖。

## 4. 分层素材设计

### 4.1 统一坐标系

所有作者层都使用相同的 `512×768 RGBA` 画布、相同原点和相同基准姿态。禁止依靠运行时人工偏移来修复导出错位。

建议从后到前按以下顺序合成：

1. `body_base`：固定躯干、四肢和尾巴；补画被头颈遮住的肩部。
2. `neck_back`：头后方颈部和肩颈毛；向头内延伸 40–56 源像素，作为变形缓冲区。
3. `head_fur_back`：耳朵、头骨、脸颊、下颌主体和可容纳独立眼球的眼窝底层。
4. `eye_left_globe`、`eye_right_globe`：虹膜、瞳孔和高光；移动范围很小。
5. `eye_left_mask`、`eye_right_mask`：每个方向各自的眼区裁剪，防止眼球穿出眼眶。
6. `face_front`：眼眶边缘、鼻口和面部关键纹理，遮住眼球移动后的边缘。
7. `blink_half`、`blink_closed`：双眼合并的半闭和全闭方向适配补丁；首版不制作左右眼不同步眨眼层。
8. `neck_front_ruff`：跨越头颈接缝的前景胸颈毛，消除剪纸接头感。
9. `collar_bell_front`：项圈和铃铛，只跟随头部变形量的 20%–30%。
10. `whiskers_front`：独立胡须层，避免网格把细线拉粗、拉断或制造双影。

第一阶段耳朵仍属于头部网格，通过耳根附近增加网格密度控制；只有样片出现耳根断裂或纹理严重拉伸时，才拆分左右耳层。

### 4.2 软形变参数

参数统一使用屏幕方向命名，避免“猫的左边”和“画面左边”混淆：

- `look_x ∈ [-1,1]`：`screen_left` 到 `screen_right`。
- `look_y ∈ [-1,1]`：`screen_up` 到 `screen_down`。
- `eye_x/eye_y ∈ [-1,1]`：眼球独立快速位移。
- `tilt ∈ [-1,1]`：屏幕左歪到屏幕右歪。

网格响应比例：

| 区域 | 变形权重 |
|---|---:|
| 头骨与面部 | 100% |
| 口鼻部 | 90%–110% |
| 上颈连接区 | 35%–55% |
| 中颈 | 15%–25% |
| 胸口与肩部锚点 | 0%–10% |
| 项圈与铃铛 | 20%–30% |

横向最大姿态的首版限制：鼻尖横移 8–12 源像素，头骨中心横移 5–8 像素，眼球额外横移不超过 4 像素、纵向不超过 3 像素；远侧脸颊压缩 5%–8%，近侧脸颊展开 2%–4%，远侧眼睛宽度最多缩小约 6%。指向侧上颈跟随约 50%，另一侧约 25%，下颈基本固定。

纵向最大姿态的首版限制：抬头时鼻口上移 5–7 源像素且喉部轻微拉长；低头时鼻口下移 5–8 像素，下颌与胸毛重叠增加，上颈缩短。

网格内部必须锁定双耳尖、双耳根、双眼四个眼角、瞳孔中心、鼻尖、口角、下颌中央、左右颈根和胸口固定点，不能只沿外轮廓布点。

## 5. 样片先行门

### 5.1 第一批视觉可行性样片

第一批只制作以下可行性资产，不批量生成正式运行时网格：

- 中心 `center`。
- 最大屏幕左视 `screen_left`。
- 最大屏幕右视 `screen_right`。
- 最大抬头 `screen_up`。
- 最大低头 `screen_down`。
- 中心方向的半闭眼和全闭眼。
- 左右歪头的 35%、70%、100% 三个非中性强度；0% 共用中心姿态。
- 由作者工具从同一网格临时渲染四个对角方向，只用于环绕预览，不放入五张关键静态样片目录，也不作为正式运行时资产。

五方向样片是可行性验证，不是最终运行时只有五个方向。它们必须使用首版允许的最大幅度，不能用“变化小到看不出问题”的演示规避难点。

### 5.2 样片输出

必须输出：

- 五方向接触表：透明棋盘、浅色背景、深色背景各一版。
- 180、280、420 像素显示高度；性能复核额外覆盖最大 520 像素。
- 鼠标环绕预览：中心加八方向，正常速度和四倍慢放各一版。
- 眨眼预览：睁眼 → 半闭 → 全闭 → 半闭 → 睁眼。
- 左歪头和右歪头各一段，包含进入、短暂停留和回正。
- 眼睛、耳根、胡须和脖子接缝的 400% 局部放大。
- 最大侧视姿态 → 点击前回中 → 动作第一帧，以及跳跃、抖动、挤压各自动作末帧 → 新待机模型的回归预览。

### 5.3 连续方向的明确实现

运行时禁止对相邻整颗头做 Alpha 交叉淡化。原因是两张不同几何状态的轮廓、眼睛和毛发会同时存在，形成双轮廓、双眼和半透明虚影。

首版采用以下方案：

1. 在离线网格工具中从同一套源层和同一网格生成方向状态。
2. 运行时先连续平滑 `look_x/look_y`，再选择最近的预烘焙状态。
3. 相邻采样点的中点是状态边界；横纵两轴迟滞宽度均为各自格间距的 10%。只有平滑参数越过“边界 + 迟滞”才换格。
4. 两轴在同一 tick 越界时，一次性按二维距离选择目标格，不依赖 X/Y 处理顺序；快速跨过多个格时不强制补播中间格。
5. 有效点击进入 `ACTION_RECENTER` 时保留当前格，到达中心后才重置选择器并开始六帧动作；动作结束、Rig 重载及故障回退后重置到中心格；缩放只失效尺寸缓存，不改变当前格。
6. 眼球在选定状态内独立连续移动，因此视线仍然快速、细腻。
7. `5×3` 仅作为作者工具和选择器流水线的低成本冒烟证明，不称为视觉候选，也不进入生产 EXE。根据最大鼻尖和纵向位移的像素预算，首个生产视觉候选直接采用 `9×5=45`：横向九点、纵向五点，并允许在脸部运动较大的区段使用非均匀采样。
8. 生成 45 状态候选后，必须使用真实“最近状态 + 迟滞”逻辑录制 420 和 520 像素慢放。420 像素下关键地标切换不超过 2.5 显示像素，520 像素下不超过 3 显示像素，并且用户主观检查无可见跳格。
9. 若 `9×5` 仍失败，不继续无限增加资源：降低头颈最大形变幅度，重新生成五张关键样片并再次请求用户确认；降低后仍不自然则停止鼠标头颈跟随，只保留独立通过的眨眼和闲置动作。

该选择把“几何插值”放在离线网格烘焙阶段完成，运行时不进行会重影的像素混合。五张关键静态样片和作者工具临时九方向预览通过后，才允许生成首个正式网格候选；正式候选仍须单独通过真实状态选择器慢放门。

### 5.4 点击动作回正

当前三组点击动画结束后会停在各自第六帧，而且三个末帧姿态不一致。新待机系统不能从不同末帧直接闪切回中性分层猫。

保持每组恰好六帧的解决方案是：新版候选中每组第一帧和第六帧都统一为基准中性姿态。动作节奏分别调整为：

- 跳跃：中性 → 蓄力 → 上升 → 最高点 → 落地缓冲 → 中性。
- 抖动：中性 → 左 → 右 → 左 → 右侧回弹 → 中性。
- 挤压：中性 → 下压 → 最扁 → 过冲拉长 → 回弹收敛 → 中性。

左键释放且判定为有效点击后，先进入 `ACTION_RECENTER`：冻结新的头颈目标，每 33ms 最多向中心移动一个方向格，同时让歪头强度最多下降一级（`100→70→35→0`），眼球同步回中；方向格和歪头级可以在同一 tick 并行推进，两者与眼球都回中后才开始六帧动作并显示气泡。通常 100–160ms、最迟 200ms 完成。若按下过程变成拖动，则取消回中并恢复普通跟随。动作结束后从当前鼠标位置重新平滑追赶。

新版候选的第一帧、第六帧与中性分层最终复合图必须在 `512×768 RGBA` 上逐字节一致并具有相同 SHA-256。候选先写入独立版本目录，不覆盖当前 `assets/keyframes`；用户看过回中节奏并批准后，才进入新版资源清单。禁止用两张整猫图交叉淡化来掩盖跳变。

## 6. 运行时架构

保留 Tk 主循环、现有 Win32 Alpha 渲染器、拖动、缩放、菜单、三组六帧动作和独立气泡窗口。新增五个职责明确的组件：

- `MotionCoordinator`：唯一的环境动作时钟和状态仲裁器。
- `CursorProvider`：通过 Win32 `GetCursorPos` 读取鼠标屏幕坐标。
- `LayeredPetAssets`：加载并验证 Rig Manifest 和所有分层素材。
- `LayerCompositor`：在固定头颈 ROI 内完成动态合成，再把 ROI 贴回缓存的完整尺寸身体工作缓冲。
- `PoseRequest`：组件间传递的不可变姿态数据。

```text
GetCursorPos
  → 相对头部屏幕锚点坐标
  → 归一化与死区
  → 眼球与头颈不同速度的平滑
  → 环境动作仲裁
  → 最近方向状态 + 迟滞
  → 眼球裁剪、眼睑或歪头状态
  → 仅合成头颈 ROI
  → 把 ROI 贴回完整尺寸身体工作缓冲
  → 将完整窗口 RGBA 图交给 UpdateLayeredWindow
```

当前 Win32 渲染器只接受完整窗口图，不能提交局部 ROI。ROI 只是减少动态计算范围；每次真正提交前必须得到完整尺寸 RGBA 工作图。该工作缓冲计入 24MiB 缓存上限和端到端性能统计。

`PoseRequest` 至少包含：

```python
@dataclass(frozen=True)
class PoseRequest:
    look_x: float
    look_y: float
    eye_x: float
    eye_y: float
    blink_stage: BlinkStage
    idle_side: IdleSide | None
    idle_level: int | None
```

纯状态机放在独立模块中，不依赖 Tk 和 Pillow，以便确定性测试。窗口类只负责把现有输入事件、协调器、素材加载器、合成器和渲染器连接起来。

## 7. 鼠标跟随

### 7.1 坐标映射

每 33ms 读取一次 `GetCursorPos`，不安装钩子，也不直接对每个鼠标事件重绘。鼠标位置相对当前头部屏幕锚点计算：

```python
target_x = tanh(dx / (pet_width * 2.2))
target_y = tanh(dy / (pet_height * 1.6))
```

中心死区为 0.03。远距离自然饱和在 `[-1,1]`，并支持多显示器和负屏幕坐标。

### 7.2 不同部位的响应速度

使用与帧率无关的指数平滑：

```python
alpha = 1 - exp(-dt / tau)
current += (target - current) * alpha
```

`dt` 限制在 0–100ms，避免系统卡顿后一次性跳到目标。

| 部位 | 时间常数 | 作用 |
|---|---:|---|
| 眼球 | 45–75ms | 最快捕捉鼠标，小幅移动 |
| 头颈联合姿态 | 180–260ms | 主体柔和跟随；颈部较小幅度由离线网格权重决定 |

首版不让头层和颈层分别选择不同方向格，否则会产生未经验证的头颈组合和接缝。眼睛先到、头颈随后；颈部柔软感由上颈到胸口逐渐衰减的网格权重以及两侧不对称压缩实现，而不是独立滞后的贴图。稳定后若头颈姿态变化小于 0.006 且眼球归一化位移小于 0.006，继续轻量采样坐标但停止调用渲染器。

## 8. 眨眼

状态机固定为：

```text
WAIT → HALF_CLOSING → CLOSED → HALF_OPENING → WAIT
```

首版参数：

- 两次眨眼间隔随机 4–9 秒。
- `HALF_CLOSING` 固定 66ms。
- `CLOSED` 固定 66ms。
- `HALF_OPENING` 固定 99ms。
- 整次眨眼约 231ms。
- 上眼睑承担约 70%–80% 的闭合，下眼睑只轻微抬升。
- 全闭时虹膜和瞳孔必须完全隐藏。
- 第一版不做单眼眨眼和连续双闪。

阶段推进使用单调时钟的已过时间，不假定 `after(33)` 精确触发；卡顿跨过多个阶段时直接进入当前正确阶段，不补播积压帧。半闭和全闭眼层必须针对每个正式方向状态由同一网格离线导出，不能把一张中心闭眼图生硬盖到所有头部方向。

## 9. 闲置歪头

### 9.1 触发条件

“闲置”按真实活动时间定义，而不是每帧抽一次概率。协调器保存最近 2 秒的归一化鼠标目标；只有窗口无点击、拖动和滚轮，且这 2 秒内目标包围范围的宽、高都小于 0.02，才开始累计闲置时间。

- 触发间隔每次从 25–70 秒重新采样。
- 若当时正在点击、拖动、缩放或恢复，延后 2–5 秒再判断，不积压待播动作。
- 200ms 内鼠标物理位移达到 16 像素，或归一化目标欧氏变化达到 0.08，定义为“明显移动”；明显移动或点击会结束歪头并进入平滑回正。

### 9.2 动作设计

左右分别制作，不能镜像，因为猫脸花纹、项圈和铃铛不对称。每侧四个强度：`0% / 35% / 70% / 100%`，运行时播放：

```text
0 → 35 → 70 → 100 → 100 → 70 → 35 → 0
```

总时长约 0.8–1.1 秒，最大头骨侧倾 8°–10°，下颌只倾 5°–7°；压缩侧颈部缩短，另一侧拉长，胸口、脚底和身体基线不动。

歪头期间暂停头颈鼠标跟随，但保留固定 50% 的眼球跟随。若在 35%、70% 或 100% 阶段被打断，则进入 `IDLE_RETURNING`，从当前强度沿同一侧逐级下降到 0，不先跳到预定下一帧；回正总时长按当前强度取 200–400ms。到达 0 之前仍暂停头颈跟随，到达 0 后重置闲置状态并让普通跟随平滑接管。若该歪头状态没有通过眼睑适配验收，则眨眼延后，不与歪头叠加。

## 10. 动画仲裁与生命周期

不同职责分开仲裁，避免“一条全局优先级”误伤窗口操作：

| 维度 | 规则 |
|---|---|
| 窗口位置 | 拖动和缩放始终可用 |
| 角色整图姿态 | 点击六帧动作优先于环境姿态 |
| 环境头颈姿态 | 闲置歪头与普通鼠标头颈跟随互斥 |
| 眼睑 | 可叠加普通跟随；点击期间暂停；未适配歪头时延后 |
| 眼球 | 普通跟随为 100%；歪头期间固定 50%；点击动作期间暂停 |

环境协调器最多只有一个活动的 `root.after(33, tick)` 句柄；现有六帧动作和气泡隐藏仍可拥有各自的短期回调。有效点击先取消眨眼和闲置序列，直接从当前歪头或侧视状态进入 `ACTION_RECENTER`，不额外走一遍慢速 `IDLE_RETURNING`，也不排队补播环境动作。点击结束后恢复中性分层姿态，再从当前鼠标位置平滑追赶。窗口销毁时必须取消环境 tick 和所有短期回调，暂停/恢复不得重复启动环境循环。

## 11. 素材结构和 Manifest

作者工程和运行时资源严格分开：

```text
assets/rig/v1/
  rig.json
  source/
    canonical-idle.png
    master.<authoring-tool-native>
    layers/
  samples/
    center/
    screen_left/
    screen_right/
    screen_up/
    screen_down/
  runtime/
    body_base.png
    look/
      <state-id>/
        back.png
        eye-left.png
        eye-right.png
        eye-left-mask.png
        eye-right-mask.png
        front.png
        blink-half.png
        blink-closed.png
    idle/
      tilt-screen-left/<035|070|100>/
      tilt-screen-right/<035|070|100>/
```

作者层始终是完整 `512×768 RGBA` 画布。`runtime/body_base.png` 也是完整画布；除此之外，所有运行时可见层都裁剪为完全相同的锁定 ROI 尺寸，并共同使用 `rig.json.runtime_roi=(x,y,width,height)` 作为唯一逻辑偏移，禁止每层另带人工偏移。

每个普通方向状态的文件集合恰好为 8 张：`back.png` 包含该方向的头颈后层，左右 `eye-*.png` 是可移动眼球，左右 `eye-*-mask.png` 是眼区运算蒙版，`front.png` 预合成脸前、颈前毛、项圈铃铛和胡须，`blink-half.png` 与 `blink-closed.png` 分别是双眼合并的方向适配补丁。左右眼不做不同步眨眼，因此合并眼睑补丁既满足首版功能又减少资产量。

每个非中性歪头强度的文件集合恰好为 6 张：`back.png`、左右眼球、左右眼罩和 `front.png`。歪头期间眨眼延后，所以不复制眼睑补丁。左右各 3 个非中性强度，共 6 个歪头状态、36 张 PNG；0% 直接复用中心普通方向。

眼罩使用 8 位灰度 `L` 模式，其余可见层使用 `RGBA`。眼罩不是可见图层，合成顺序固定为：移动当前方向的眼球小图 → 以眼罩作为 `paste/composite` 的运算蒙版裁切 → 合成到 `back.png` → 叠加 `front.png` → 按阶段叠加对应眼睑补丁。眼球位移相对于每个状态自己的眼睛锚点计算；换方向格时继续使用同一个归一化 `eye_x/eye_y`，不能重置瞳孔。

若正式方向数为 `N`，新增运行时 PNG 数量精确为 `1 + 8N + 36`；生产 `9×5=45` 候选为 397 张。数量多不等于全部常驻内存：方向状态按需解码，缓存只保存缩放后的不可变身体和方向小层，不缓存带连续眼球位置的完整复合帧；所有源尺寸、缩放尺寸和完整尺寸工作缓冲合计硬上限 24MiB，按字节 LRU 淘汰。

`rig.json` 是唯一运行时权威来源，必须记录：格式版本、基准图哈希、画布、动态 ROI、层序、全部方向采样点、每个状态 ID 与参数、眼球范围、每状态眼睛锚点、眨眼参数、歪头参数、每个文件的模式、尺寸、SHA-256 和精确文件集合。运行时不再设置重复的 `pose.json`。加载器拒绝缺失文件、多余文件、错误模式或尺寸、哈希不符和未知格式版本。

动态 ROI 的初始候选为源画布 `x=0, y=160, width=320, height=416`。五方向与左右歪头完成后，用全部动态像素联合包围盒外扩 16 源像素复核；动态像素本身必须始终距离 `512×768` 画布边缘至少 16 像素，否则降低该方向幅度并重新出样片。候选能覆盖则锁定，不能覆盖则在画布内扩展到外扩后的联合包围盒。运行时只重合成锁定 ROI，身体其余部分使用缓存静态图。

EXE 只打包生产 `rig.json` 和 `runtime/`；`source/`、`samples/`、作者工具原生工程、接触表、GIF 和 QA 报告全部排除。作者阶段另存绑定 QA 报告，包含网格拓扑、原始顶点、各关键姿态顶点、翻转数量和面积比例；这份报告用于验收但不进入 EXE。

## 12. Alpha、身份与形变验收门

以下任一项失败都停止进入程序接入：

- 中心分层重新合成后，双眼角和鼻尖相对基准偏移超过 1 源像素，耳尖与毛发外轮廓偏移超过 2 源像素。
- 白色额纹、脸颊花纹、耳内纹理、脸型、眼距、项圈或铃铛发生身份漂移。
- 网格单元翻转；脸部关键区域面积比例超出 `0.88–1.12`；一般头颈网格超出 `0.78–1.25`。
- 胡须变粗、断裂、双影或漂浮。
- 头颈接缝出现透明裂缝、双重暗边、重叠硬线或毛发方向突变。
- 最终完整复合图和每张可见 ROI 层的外围 1 像素不全透明；任意可见 RGBA 层在 `Alpha=0` 时 RGB 未清零。灰度眼罩只检查尺寸和值域，不执行透明 RGB 规则。
- 主体外轮廓半透明带在黑、白、灰背景出现异常粉、紫或其他色相残边；角色自身合法的暗毛、瞳孔和项圈不属于“黑边”误报。
- 为消除边缘而把 Alpha 二值化。
- 身体在锁定 ROI 外随方向状态变化；脚底基线偏离 `y≈736`。
- 420 像素显示尺寸下，相邻方向切换造成双眼角、鼻尖或耳尖超过 2.5 显示像素；520 像素下超过 3 显示像素。
- 瞳孔接触或穿过眼罩边界；全闭眼仍露出绿色虹膜。
- 左右歪头只是整头旋转，或颈部两侧形变量相同。
- 环绕预览出现双轮廓、双眼、半透明重影或明显跳格。
- 最大侧视、最大左歪头、最大右歪头及歪头中途点击进入，或三组动作开始、结束、回到待机的任一阶段出现明显闪切；新版每组第一帧和第六帧与中性复合图哈希不一致。

最高视觉风险是原图没有提供头后方完整脖子和肩部。这部分必须补画。若补画毛发方向、光照或卷毛质感与原猫不一致，中心重新合成门就不能通过，后续方向素材停止制作。

## 14. 性能与包体预算

当前测得基线：

- 稳定 EXE 为 `桌面宠物-6帧猫耳颜文字版.exe`，大小约 29.39MiB，SHA-256 为 `594EE6FD95BEA7B681551196F448FB3DD62B9CC49BECAE19DB3A0477776842B0`。
- 静止工作集合计约 100.69MiB，CPU 接近 0%。
- 最大 `347×520` 显示尺寸的单次微基准：完整图 LANCZOS 缩放约 6.998ms，Alpha 预乘约 1.863ms，单层合成约 0.376ms。
- 上述数字不含 DIB 创建和系统窗口提交，不能当作完整帧性能承诺。

发布门：

- 活跃跟随目标 30fps，不按原始鼠标事件无限重绘。
- 默认尺寸完整合成与提交 P95 不高于 10ms；最大 520 像素 P95 不高于 20ms。内部纯合成目标分别为 4ms 和 8ms。
- 任意 10 秒持续移动记录至少提交 270 帧，平均不低于 27fps；P95 帧间隔不高于 50ms，非系统卡顿情况下不得连续出现超过 100ms 停顿。
- 活跃跟随 60 秒内，PyInstaller 父子进程 `TotalProcessorTime` 增量求和除以墙钟时间，折算为单逻辑核占用不高于 25%。测试机总 CPU 同步记录但只作环境参考，不另设冲突门槛。
- 稳定后停止重绘，只保留轻量鼠标采样。
- 父子进程工作集总和必须同时满足不高于 150MiB、且相对同轮稳定版增加不超过 30MiB；静置 30 分钟增长不超过 10MiB。
- 新候选固定命名为 `桌面宠物-自然跟随候选版.exe`，不高于 50MiB；其中打包后的生产 Rig 资源不高于 20MiB。若超过，先优化运行时裁剪和压缩，不把作者源文件塞入 EXE。
- 冷启动不比稳定版慢 20% 以上，且当前测试机绝对时间不高于 4 秒。

性能复现协议固定为：280 和 520 像素两个显示高度；每个高度先预热 3 秒，再按“4 秒圆周 + 3 秒横扫 + 3 秒锯齿”的确定性目标轨迹运行 5 轮。端到端时长从协调器更新开始计到 `UpdateLayeredWindow` 返回，包含状态选择、懒加载、缩放、眼罩裁切、合成、预乘 Alpha、DIB 和系统提交；5 轮必须分别满足 P95 与帧率门。另做 600 次纯合成样本，验证默认和最大尺寸的 4ms/8ms内部目标。

实现上只缓存缩放后的不可变身体和方向小层，跨源尺寸与最多三个显示高度执行 24MiB 字节级 LRU；不缓存带连续眼球位置的完整复合帧。连续参数只在跨过迟滞边界、眼球归一化位移超过 0.006 或动作阶段变化时触发重绘，不能在每个 30fps 时钟都重新对完整 `512×768` 图做 LANCZOS 缩放。第一版可保留当前每帧创建 DIB 的实现，只有完整帧基准证明超预算后才复用 DIB 资源。

上一版尚未完成的人工 9 次点击、四边拖动和真实桌面截图不能由本项目的样片或新实机录像倒推为“已通过”；两版证据分开归档。

## 15. 失败回退

- Rig 包缺失、哈希或尺寸错误、Manifest 版本不兼容：整套新环境功能禁用，回退当前六帧整图桌宠。
- `GetCursorPos` 失败：姿态缓慢回正，不影响点击和窗口操作。
- 合成异常：停止环境 tick、释放 Rig 缓存、显示稳定中性整图，再回退旧六帧模式；诊断信息最多写一次到 `%LOCALAPPDATA%\DesktopPet\logs\runtime.log`。
- 五方向静态图不通过：停止，不写运行时代码。
- 环绕预览仍有重影或跳格：先判断是网格质量还是状态密度；问题未解决不扩展整套素材。
- 眨眼或歪头接缝不自然：返回分层绑定，不进入 EXE。
- 点击末帧回待机跳变：先修六帧动作回正，不用程序淡化掩盖。
- 跟随效果不达标时，可以只发布已经独立通过的眨眼和闲置动作，但不能把低质量跟随称为完整版本。
- 当前稳定 EXE、已确认 SHA-256 和独立提交作为立即回退点；新 EXE 不覆盖旧文件。

## 16. 分阶段执行顺序

1. 只拆中心中性姿态，补全肩颈和眼窝。
2. 重新合成中心层，与基准图做像素和视觉差异检查；不过门立即停止。
3. 制作最大屏幕左、右两个横向状态，验证不对称头颈形变。
4. 补最大抬头、低头，完成五方向接触表。
5. 用同一网格离线导出中心加八方向环绕预览，验证连续方向方案。
6. 制作半闭、全闭眼和眨眼预览。
7. 先制作铃铛所在的高难侧歪头，再制作另一侧，完成回正预览。
8. 在独立候选目录把三组六帧动作的第一帧和第六帧统一为中性姿态，验证回中进入动作及末帧回待机。
9. 用户确认猫的身份、脖子自然度、眼神、眨眼、歪头和回正观感。
10. 通过后生成 `5×3` 流水线冒烟样本，再直接生成 `9×5=45` 生产视觉候选并用真实迟滞选择器慢放；通过像素和观感门后生成生产 Rig Manifest，失败则降低幅度并重新请求确认，不继续扩大资源网格。
11. 再编写运行时实施计划，建立独立功能分支，实现协调器、加载器、合成器和回退。
12. 自动测试、Windows 实机、性能、包体和归档验证全部通过后，才交付新名称 EXE。

## 17. 用户视觉确认点

自动测试不能替代以下判断，必须由用户看样片确认：

- 仍然是同一只猫，脸型、花纹、眼距和神态没有被拉坏。
- 脖子两侧形变自然，没有皮影戏或塑料拉伸感。
- 瞳孔跟随显得可爱，不惊恐、不斗鸡眼、不漂浮。
- 闭眼像猫咪眨眼，不是贴了一条粗线。
- 左右歪头的幅度、停顿和回正速度舒服。
- 环绕移动没有肉眼可见跳格、双轮廓或毛发虚影。
- 三组点击动作结束回待机不突兀。
- 浅色和深色实际桌面上的边缘都干净，无粉边和彩边。

用户批准本规格后，下一步只编写“素材样片实施计划”并开始中心分层与五方向样片，不直接批量生产 45 状态，也不直接修改运行时代码。样片获批后再单独编写“运行时实施计划”。
