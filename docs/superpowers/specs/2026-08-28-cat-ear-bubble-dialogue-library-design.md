# 猫耳蝴蝶结气泡与 600 句动作台词库设计规格

## 目标

深化当前“桌面宠物 6 帧无粉边版”，不修改角色形象、三组动作素材、动作顺序和每组 6 帧的节奏。所有互动气泡统一改为用户选定的第 4 款“猫耳蝴蝶结”风格；气泡外观使用透明 PNG 素材，文字继续由程序实时绘制。为跳跃、压扁回弹、左右抖动分别建立 200 条动作专属内容，每组由 180 条中文台词和 20 条纯颜文字组成，共 600 条。每次有效点击开始一个动作时，只从该动作对应的库中随机显示一条。

## 已确认体验

- 口吻统一为猫猫第一人称、可爱俏皮。
- 跳跃台词偏兴奋、轻快和小得意。
- 压扁回弹台词偏软萌吐槽、撒娇和治愈。
- 左右抖动台词偏元气、搞怪和节奏感。
- 每个动作固定使用 20 条精致猫系颜文字台词，三组共 60 条；其余每组 180 条、共 540 条继续使用已审定的中文猫猫第一人称台词。
- 颜文字采用用户确认的 A 方案，允许 `₍^. .^₎⟆` 这类 6–10 码位纯颜文字；不使用系统字体，也不以 Emoji、超长装饰或重复符号堆砌内容。
- 点击仍按 `jump -> squash -> shake` 固定顺序轮流触发；动画忙碌期间被忽略的点击不显示新气泡。
- 每个成功开始的动作从本动作的 200 句中等概率随机抽取一句，并排除该动作上一次显示的句子，避免立即重复。

## 方案比较

1. **透明 PNG 气泡皮肤 + PIL 实时文字 + Win32 逐像素 Alpha（采用）**：保留图片质感和动态文字能力，600 句只保存文本，气泡边缘继续使用平滑 Alpha，不出现矩形底色或颜色键杂边。
2. **Tk Canvas 绘制粉色气泡**：实现简单，但猫耳、蝴蝶结、高光和柔和圆角质感有限；继续使用普通 Tk 窗口也难以得到真正透明的气泡外轮廓。
3. **预渲染 600 张完整气泡图片**：字体效果固定，但资源重复、EXE 体积显著增加，任何台词或字体调整都要重新生成整套图片，不利于维护。

## 气泡视觉资产

以已选第 4 款为唯一视觉方向，重新制作可用于程序的干净素材，而不是直接裁切对比稿。素材不包含文字、角色、桌面背景、阴影底板或白色矩形：

- `assets/bubble/cat-ear-bow-body.png`：透明背景，奶油浅粉色近乎不透明主体，柔和圆角，两只小猫耳，右下角小蝴蝶结，极细玫粉边线和克制高光。
- `assets/bubble/tail-down.png`、`tail-up.png`、`tail-left.png`、`tail-right.png`：四个同色透明尾巴覆盖层。程序根据气泡位于角色的上、下、左、右选择正确方向，尾巴始终指向角色。
- 主体与尾巴使用真实 Alpha；禁止 `#ff00ff` 色键、厚白边、黑灰描边、硬直角、尖锐三角尾巴和外部投影。
- 气泡保持已审定的 `768x384` 源图比例，默认正文主体显示为 `280x140` 像素；运行时只在屏幕工作区不足时做等比缩小，不拉伸猫耳或蝴蝶结。

图片生成遵循 `imagegen` 工作流。生成后执行透明通道、外边框、可见残色和实际桌面截图检查；对透明像素统一清零隐藏 RGB，避免缩放后形成彩边。

## 字体与文字渲染

中文采用 Google Fonts 官方仓库中的 `ZCOOL KuaiLe Regular`（站酷快乐体），文件名为 `ZCOOLKuaiLe-Regular.ttf`。精致颜文字采用 Google Fonts 官方仓库中的 `Noto Sans` 与 `Noto Sans Math` 组成确定性逐字符回退链：上游 `NotoSans[wdth,wght].ttf` 在项目中规范化命名为 `NotoSans-Variable.ttf`，覆盖下标括号等通用符号；`NotoSansMath-Regular.ttf` 补充 `⟆` 等数学符号。三套字体均随 EXE 内置，许可证均为 SIL Open Font License 1.1。

- 字体文件保存为 `assets/fonts/ZCOOLKuaiLe-Regular.ttf`，运行时通过 `asset_path` 读取，不依赖用户电脑预装字体，也不向 Windows 字体目录安装文件。
- 颜文字回退字体保存为 `assets/fonts/NotoSans-Variable.ttf` 与 `assets/fonts/NotoSansMath-Regular.ttf`；程序按字符检查真实字形覆盖后选择字体，禁止把 `.notdef` 方框当成可用字形。
- 三套字体的许可文件固定保存为 `assets/fonts/licenses/ZCOOLKuaiLe-OFL-1.1.txt`、`assets/fonts/licenses/NotoSans-OFL-1.1.txt`、`assets/fonts/licenses/NotoSansMath-OFL-1.1.txt`；根目录 `THIRD_PARTY_NOTICES.txt` 逐项记录本地文件名、上游原文件名、版权、许可证、Google Fonts 上游 URL、固定字节数和 SHA-256。EXE 内嵌全部许可，最终 `交付` 目录也放置用户可直接阅读的三份许可和 notices。
- 文字使用 Pillow `ImageDraw` 在气泡 RGBA 副本上实时绘制，再交给逐像素透明窗口渲染器。
- 默认文字颜色为深玫瑰棕，水平和垂直居中；不使用厚描边。只有必要时使用极细的浅色抗混叠保护，不制造白边。
- 字号按气泡缩放比例计算；单行显示，不换行，不遮挡猫耳、蝴蝶结或尾巴安全区。
- 中文台词继续使用共享生产字号 28；纯颜文字使用共享生产字号 40。渲染器先按字符分段测量各字体 run 的总宽度，再把整行作为一个整体居中绘制；缩小时所有 run 使用同一缩放比例。

新增共享 `FontRunResolver`，验证器和 `BubbleComposer` 必须调用同一套解析与布局结果，不能各自测量。解析器只从 `asset_path` 加载上述内置字体；Noto Sans Variable 固定使用 `wght=400`、`wdth=100`，按真实 `cmap` 以 `Noto Sans -> Noto Sans Math` 的顺序逐字符选择字体，两者都有字形时固定优先 Noto Sans，连续使用同一字体的字符合并为一个 run。每个布局结果包含字体、run 文本、x advance、共同 baseline、ascent/descent、ink bbox 和总 advance；测宽、居中、缩放和像素取整复用这一结果。

若字体文件缺失或损坏，或字符在两套 Noto 字体的 `cmap` 中均不存在，验证和运行时都以包含动作、台词及 `U+XXXX` 的明确错误闭锁失败。禁止调用 `ImageFont.load_default()`、Tk 字体、字体家族名查找、Windows Fonts API 或任何系统字体回退，也禁止显示 `.notdef` 方框。

## 逐像素透明气泡窗口

当前 `BubbleWindow` 的 Tk Canvas 白色矩形实现将被替换。新的气泡窗口仍使用无边框 `Toplevel` 管理生命周期和位置，但实际像素由现有 `LayeredWindowRenderer` 通过 `UpdateLayeredWindow(..., ULW_ALPHA)` 输出。

显示流程为：选择台词 -> 计算方位和缩放 -> 组合气泡主体与对应尾巴 -> 使用内置字体绘制文字 -> 将最终 RGBA 图送入气泡窗口的分层渲染器。气泡窗口继续跟随置顶开关、角色拖动和显示计时；约 1.8 秒后隐藏。气泡矩形不得与角色矩形相交，并限制在当前显示器工作区内。

## 台词库结构与质量约束

台词保存为独立 UTF-8 JSON 数据文件 `assets/dialogue/phrases.json`，键固定为 `jump`、`squash`、`shake`，每个键对应恰好 200 个字符串。代码不把 600 句话硬编码进窗口逻辑。

每句话必须同时满足：

- 每条内容按 Python `len(text)` 计为 6 至 10 个 Unicode code points，首尾不得为空白；中文字符、颜文字符号和纯颜文字内部的 ASCII 空格都计入长度。
- 三组共 600 句全局唯一，不存在空字符串或仅标点内容。
- 至少 90% 的内容为 7 至 9 个码位；该比例按全库 600 条统计。6 和 10 码位只用于保持语义或容纳紧凑颜文字，颜文字候选优先选择 7 至 9 码位，为中文台词保留必要余量。
- 使用最终字体和默认字号测量后，文字宽度必须位于 `230 px` 气泡正文安全区内：中文按 28 px 验收为 `120–230 px`，纯颜文字按 40 px 验收为 `60–230 px`。任何欠宽、超宽或空白渲染结果都直接使素材验证失败。
- 每个动作恰好 20 条纯颜文字、180 条中文第一人称台词；`jump` 颜文字表达腾空和欢呼，`squash` 表达圆脸、挤压和回弹，`shake` 表达左右摇爪、晃动和眩晕。
- 验证顺序固定为先执行 `is_kaomoji_phrase(text)` 分类，再套用类别规则。每个动作分类结果必须恰好为 20 条 `True` 和 180 条 `False`；仅 `False` 的中文台词要求包含“我 / 本喵 / 本猫 / 猫猫”之一，仅 `True` 的纯颜文字免除第一人称标记。
- 纯颜文字不得包含 CJK、假名、韩文、控制字符、零宽连接符、变体选择符、区域指示符、键帽组合字符、彩色 Emoji/Extended Pictographic、未经批准的组合附加符或连续两个及以上 ASCII 字母。它必须含一组已批准的左右包围符或成对括号，并在包围区内含眼睛标记，在包围区内或紧邻右侧含猫耳、猫爪、挥手或动作标记。批准字符集合、禁止 Unicode 范围和结构集合均以源码常量显式列出并由单元测试锁定，不使用语言环境或系统字体推断。
- 纯颜文字只使用两套 Noto 回退字体逐字覆盖的紧凑形式；首批必须包含用户指定风格 `₍^. .^₎⟆`。任何字符若两套回退字体均缺失，整句直接使发布验证失败，禁止悄悄调用系统字体。
- 60 条颜文字以网站分类作为风格参考后重新组合和筛选，不批量复制站点内容，不据此推断站点内容许可；最终只交付项目内已逐条审定的短串。
- 不包含辱骂、攻击、低俗、惊吓、政治、广告、联系方式或需要联网解释的内容。

为避免 200 条只是机械换词，每组按 5 个语义子类各准备 40 条；每个子类固定为 36 条中文台词和 4 条纯颜文字，因此每个动作精确得到 180 条中文和 20 条颜文字：

- `jump`：起飞、腾空、挑战、撒娇、庆祝。
- `squash`：软团、回弹、吐槽、治愈、撒娇。
- `shake`：左右、抖毛、提神、节奏、搞怪。

运行时加载后先验证键、数量、字符串类型、颜文字分类及每动作 `180+20` 配额。开发构建额外执行完整内容、字符数、全局唯一性、字体覆盖和像素宽度检查。随机选择器为每个动作分别记录上一条，只排除立即重复，不改变其余 199 条的均匀概率。

颜文字验证还必须统计每个动作的颜文字数量恰好为 20，并使用与 `BubbleComposer` 相同的 run 分段、字号 40 和安全区宽度进行测量。验证器输出中文/颜文字分类计数、两套回退字体的缺字结果及最小/中位/最大宽度；测试覆盖“仅第一字体缺字但第二字体可用”和“两套字体都缺字”的边界。

## 文件与组件边界

- `src/desktop_pet/bubble.py`：气泡窗口、图像组合、文字绘制和显示计时。
- `src/desktop_pet/dialogue.py`：台词库加载、结构校验和无立即重复随机选择。
- `src/desktop_pet/font_runs.py`：内置字体 `cmap` 检查、确定性逐字符回退、共享 run 布局和测宽；验证器与渲染器共同依赖它。
- `src/desktop_pet/window.py`：在动作成功启动时向台词选择器传入当前动作，不承担文本内容或渲染细节。
- `assets/bubble/`：猫耳蝴蝶结气泡主体和四方向尾巴 PNG。
- `assets/fonts/`：站酷快乐体、Noto Sans、Noto Sans Math；`assets/fonts/licenses/` 保存三套固定命名的 OFL 文本。
- `assets/dialogue/phrases.json`：三组共 600 句台词。
- `tools/validate_dialogue.py`：数量、字符、唯一性、字体覆盖和显示宽度验证。
- `desktop_pet.spec`：把气泡、字体、许可和台词数据打包进单文件 EXE。

## 构建与交付

继续在 `codex/desktop-pet-6-frame-alpha` 分支深化，保持三组各 6 帧和现有逐像素 Alpha 角色窗口。PyInstaller 单文件 EXE 的 datas 清单必须覆盖 `assets/keyframes/`、`assets/bubble/`、`assets/fonts/`、`assets/fonts/licenses/`、`assets/dialogue/` 和根目录 `THIRD_PARTY_NOTICES.txt`。用户无需安装字体或 Python，仍可直接双击运行。成品使用新名称，避免覆盖上一份“6 帧无粉边版”；交付目录同时保留第三方字体许可说明。

构建后使用 PyInstaller archive viewer 或等效检查核对每个确切归档路径，并由 EXE 启动探针证明三套字体均能从 `_MEIPASS/assets/fonts/...` 打开；归档内和 `交付` 目录中的字体、OFL 与 notices 必须和许可清单中的字节数及 SHA-256 一致。

## 验收标准

- 所有互动均使用第 4 款猫耳蝴蝶结风格，不再出现旧白色 Canvas 气泡。
- 气泡主体由 PNG 素材提供；中文由内置站酷快乐体实时绘制，精致颜文字由内置 Noto 回退字体链实时绘制。
- Noto 回退覆盖“仅 Noto Sans 有字形”“仅 Noto Sans Math 有字形”“两者都有时优先 Noto Sans”“两者都没有时明确失败”四种边界；跨两个 run 的验证宽度与最终 RGBA 实际 bbox 一致。
- 气泡窗口使用逐像素 Alpha，外部完全透明，圆角、猫耳和蝴蝶结无粉边、白边或矩形底。
- 气泡位于角色外部，尾巴方向正确；拖动、缩放、置顶切换和多显示器边缘场景仍正常。
- `jump`、`squash`、`shake` 各恰好 200 条，共 600 条全局唯一，全部通过 6 至 10 码位、字体覆盖和像素宽度验证。
- 每个动作恰好 20 条颜文字和 180 条原中文台词；三组共 60 条颜文字、540 条中文，且保留用户指定的 `₍^. .^₎⟆` 风格。
- 每次有效点击只从当前动作库中随机抽取一条，并且同一动作不会连续两次显示同一句。
- 三组动作继续各 6 帧，动作顺序、透明角色轮廓、左键拖动、滚轮缩放、右键菜单和双击 EXE 运行能力不回归。
- 自动测试、台词验证、图像 Alpha 验证、PyInstaller 构建、归档资源检查和 EXE 启动探针通过；测试还证明删除或损坏任一内置字体时干净失败且绝不调用系统字体。另提供实际桌面截图检查气泡视觉。

## 非目标

- 不增加新动作、语音、音效、自动聊天、联网内容、设置窗口或开机启动。
- 不安装系统字体，不要求用户管理额外依赖。
- 不修改 18 张角色关键帧，不恢复 30 帧运行时素材。
