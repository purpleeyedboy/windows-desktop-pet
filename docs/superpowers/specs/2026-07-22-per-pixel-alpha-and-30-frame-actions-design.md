# 桌面宠物逐像素 Alpha 与 30 帧动画设计规格

## 目标

在现有 Windows 桌面宠物基础上完成两项升级：

1. 彻底移除角色外轮廓的洋红色描边。主角色窗口不再使用 Tk 的 `#ff00ff` 色键透明，而改为 Windows 逐像素 Alpha 合成，完整保留 PNG 缩放后的半透明抗锯齿边缘。
2. 将 `jump`、`squash`、`shake` 三组动画分别从 6 个关键帧扩充到 30 帧。保留现有 18 张图片作为不可变关键帧，新增 72 张过渡帧，最终得到 90 张 `512×768 RGBA` 动画帧。

最终仍交付一个可以直接双击运行的 `dist/桌面宠物.exe`，并保留拖动、点击动作、气泡、滚轮缩放、置顶开关、尺寸菜单、单实例和退出功能。

## 已确认根因

当前角色窗口的背景和 `Label` 背景均为 `#ff00ff`，再通过 Tk 的 `-transparentcolor` 让 Windows 隐藏完全相等的洋红像素。角色图片从 `512×768` 用 LANCZOS 缩放到默认约 `187×280` 时，PNG 边缘的半透明像素会与洋红背景混合，产生不再等于 `#ff00ff` 的粉紫色像素。色键只能移除纯洋红，因此混合像素形成均匀的粉色外轮廓。

这个问题属于运行时合成路径，而不是继续清理原 PNG 就能解决的问题。更换色键只会改变残边颜色；将 Alpha 二值化虽然能隐藏残边，但会牺牲毛发和耳朵的平滑边缘。因此采用逐像素 Alpha 作为正式修复。

## 方案比较

### 方案 A：Win32 逐像素 Alpha，推荐并采用

保留 Tk 负责事件循环、菜单、计时器和气泡生命周期；主角色窗口的像素显示改由 Win32 `UpdateLayeredWindow` 完成。每帧使用预乘 Alpha 的 BGRA DIB 传给 Windows，系统直接读取每个像素的 Alpha，不再使用颜色键。

优点：根治粉边、保留抗锯齿、无需大型 GUI 框架、可以复用现有交互代码。主要风险是 Win32 资源管理和 Tk 窗口句柄生命周期，需要通过纯函数测试、GDI 对象释放和真实 EXE 冒烟检查控制。

### 方案 B：继续使用 Tk 色键并二值化边缘

缩放后将 Alpha 强制为 0 或 255，可消除粉边，但会让猫毛、耳朵和尾巴边缘出现锯齿。只作为非 Windows 或逐像素渲染不可用时的诊断退路，不作为交付方案。

### 方案 C：改写为 PySide6、WPF 或其他 GUI 框架

也能获得逐像素透明，但会扩大依赖和重构范围。此前 PySide6 下载已多次超时；现有 Tk 交互逻辑已经稳定，因此没有必要整体重写。

## 逐像素 Alpha 窗口架构

新增 `src/desktop_pet/layered_window.py`，职责如下：

- 将 Pillow `RGBA` 图像转换为 Windows 需要的预乘 Alpha `BGRA` 字节序。
- 创建自顶向下的 32 位 DIBSection，将像素复制到内存 DC。
- 设置主窗口 `WS_EX_LAYERED` 和工具窗口样式。
- 使用 `UpdateLayeredWindow(..., ULW_ALPHA)` 同时更新窗口位置、尺寸和像素。
- 每次渲染后恢复并释放选入的 GDI 对象、位图、内存 DC 和屏幕 DC；失败时抛出带 Win32 错误码的异常。

`PetWindow` 的变化：

- 移除角色 `Label`、`ImageTk.PhotoImage`、`#ff00ff` 背景和 `-transparentcolor`。
- 将左键、拖动、右键和滚轮事件直接绑定到 Tk 根窗口。
- LANCZOS 缩放仍由 Pillow 完成，但缩放后的 RGBA 直接交给逐像素渲染器，不与任何背景色预合成。
- 继续用角色脚底中心作为缩放和换帧锚点。
- 默认置顶和置顶开关同步控制 Tk 属性及窗口扩展样式。

透明区域必须保持 Alpha 0；Windows 负责最终合成。运行时不得再出现 `LWA_COLORKEY`、`-transparentcolor` 或角色背景色键。

## 气泡窗口

气泡本身按需求为不透明白色背景，因此不再需要洋红色透明键。气泡改为无边框的白色不透明工具窗口，使用深色文字和边框；允许窗口四角保持白色矩形背景，重点保证不遮挡角色、不越出屏幕和不出现粉边。气泡仍在约 1.8 秒后隐藏，并跟随角色拖动、缩放和置顶状态。

## 30 帧资产布局

现有 6 帧先复制到不可变关键帧目录，并记录 SHA-256：

```text
assets/keyframes/
  jump/00.png ... 05.png
  squash/00.png ... 05.png
  shake/00.png ... 05.png
  manifest.json
```

最终运行时目录保持原结构，但每组包含 `00.png` 至 `29.png`：

```text
assets/pet/
  jump/00.png ... 29.png
  squash/00.png ... 29.png
  shake/00.png ... 29.png
```

原关键帧在 30 帧序列中的固定位置为：

| 原关键帧 | 最终帧号 |
|---|---:|
| `00` | `00` |
| `01` | `06` |
| `02` | `12` |
| `03` | `17` |
| `04` | `23` |
| `05` | `29` |

五个区间新增帧数为 `5 / 5 / 4 / 5 / 5`，总计 24 张。中央动作区间帧数略少，用于保持跳跃峰值转向、压扁反转和抖动高速换向的节奏。

## 补帧算法

三组动作由三个智能体并行处理，每个智能体只写自己的动作目录和 QA 输出：

- `jump_frames` 专属目标：将跳跃动作扩充为 30 帧，保持六个关键帧哈希不变，并交付跳跃接触表、双速 GIF 和统计报告；只写 `assets/pet/jump` 与对应 QA 文件。
- `squash_frames` 专属目标：将压扁回弹动作扩充为 30 帧，保持六个关键帧哈希不变，并交付压扁接触表、双速 GIF 和统计报告；只写 `assets/pet/squash` 与对应 QA 文件。
- `shake_frames` 专属目标：将左右抖动动作扩充为 30 帧，保持六个关键帧哈希不变，并交付抖动接触表、双速 GIF 和统计报告；只写 `assets/pet/shake` 与对应 QA 文件。

主智能体专属目标是实现逐像素 Alpha 窗口、升级运行时和验证器、整合三个动作目录，并完成测试、打包与 EXE 验收。四个目标之间不共享写入目录；资产生成智能体不得修改程序代码、公共测试或其他动作目录。

补帧以确定性运动补偿为主，避免逐帧图像生成造成换脸、毛色漂移和肢体数量变化：

1. 对两个相邻关键帧的 Alpha bbox、质心和尺度做粗对齐。
2. 在预乘 Alpha 的 RGBA 空间计算双向稠密运动场。
3. 使用平滑缓入缓出时间曲线，分别将前后关键帧向中间时刻变形。
4. 对两个变形结果做遮挡感知的预乘 Alpha 合成。
5. 将 Alpha 0 像素的 RGB 归零，清除隐藏颜色残留。
6. 若个别区间出现尾巴撕裂、双耳、透明孔洞或明显拓扑错误，只为该区间增加少量参考编辑锚点；不独立生成全部 24 帧。

OpenCV/Numpy 仅作为离线资产生成依赖，不进入桌宠运行时代码和 PyInstaller 分析入口。原始关键帧全部来自已确认的角色素材，算法只生成它们之间的过渡状态。

## 动画节奏

运行时从每组实际加载 30 帧。默认间隔调整为约 33 毫秒，每组动作约 1 秒。动画期间继续忽略新的动作点击，但允许拖动。播放结束后恢复中性基准帧。

## 自动验证

资产验证器升级为 30 帧契约，并生成机器可读报告。每组必须满足：

- 恰好包含 `00.png` 至 `29.png`，总计 30 张。
- 每张均为 `512×768 RGBA`，Alpha 同时包含 0 和 255，不得为空帧。
- Alpha 0 像素的 RGB 全部为 0。
- 最外圈不得包含非透明像素；主体不得被画布裁切。
- 最大连通主体占有效像素的绝大部分，不得出现明显孤立噪点。
- 新 `00/06/12/17/23/29` 与关键帧清单中的原图 SHA-256 完全一致。
- 相邻帧质心、bbox、有效 Alpha 面积和轮廓 IoU 不得出现超阈值突跳。
- 半透明边缘不得形成洋红、紫、青、绿或蓝色高饱和残边链。

窗口测试必须证明：

- RGBA 到预乘 BGRA 的数值正确。
- 主角色渲染路径不再调用颜色键透明。
- 窗口仍为无边框、分层窗口，默认置顶。
- 拖动、点击轮播、滚轮、菜单、气泡和单实例行为不回归。

## 视觉 QA

每个动作生成：

- 30 帧接触表。
- 正常速度 GIF，约 30 FPS。
- 0.25 倍慢速 GIF。
- 连续性与边缘统计 JSON。

最终再生成一张三组共 90 帧总览图。人工检查同一只猫的脸、眼睛、耳朵、橘白花纹、身体比例、尾巴、脚爪和质感是否稳定；拒绝双轮廓、重影、糊脸、断肢、拉丝、透明孔洞、阴影、光晕和新增特效。

## 打包与验收

`build.ps1` 继续验证素材、运行测试并使用 PyInstaller 构建单文件 EXE。最终验收证据包括：

- 完整测试套件通过。
- 90 帧资产验证通过，18 张关键帧哈希不变。
- PyInstaller 不报告缺失 Tk 或新模块。
- 实际启动 EXE 后只有一个可见角色窗口。
- 窗口具备 `WS_EX_LAYERED`，但不使用颜色键透明。
- 默认置顶、无边框、拖动、点击动作、滚轮缩放、右键菜单和退出可用。
- 角色轮廓在默认尺寸及小、中、大三档均无粉色或其他彩色边缘。

## 非目标

- 不更换角色、不改变三种动作语义。
- 不增加音效、物理移动、自动漫游或开机启动。
- 不把 OpenCV/Numpy 打进最终 EXE。
- 不以 Alpha 二值化作为正式修复。
