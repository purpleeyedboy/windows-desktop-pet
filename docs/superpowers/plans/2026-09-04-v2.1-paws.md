# V2.1-PAWS Dual Forepaw Mouse Press Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an independently packaged V2.1 test feature in which two alpha-masked forepaws safely press, hold, push, release, cancel, and yield control of the Windows pointer.

**Architecture:** Keep pointer ownership in a pure, deterministic `PawPressController` behind a replaceable `PointerInputAdapter`; the Win32 adapter is the only code allowed to invoke capture, button injection, cursor movement, or `ClipCursor`. A separate compositor maps authored, non-rectangular alpha masks from source coordinates through the current image/window transform, so the existing head/body/eyes/Alpha/head-neck/eye-follow pipeline and approved files remain unchanged.

**Tech Stack:** Python 3.11, Pillow, ctypes/Win32, Tk, pytest, PyInstaller, GitHub Actions PowerShell.

## Global Constraints

- Start at HEAD `c3b218df9dd0cfc84d96231701e771f0382388e1`; do not switch to an old branch.
- Do not change approved cat head, body, eye, Alpha, head-neck, eye-follow assets or idle head angles.
- Do not implement ears, hand licking, hunger, drag/drop, or file feeding and never access user files.
- Automated tests use only a fake adapter and never move or click the real pointer.
- Every exit, focus loss, interrupt, exception, and ownership loss releases capture, the left button, and `ClipCursor`, and restores neutral paws.
- Windows acceptance, automated evidence, artifact hash, and user visual acceptance remain separate gates.
