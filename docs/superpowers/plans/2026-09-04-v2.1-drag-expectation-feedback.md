# Desktop Pet V2.1 Drag Expectation Feedback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:test-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a non-destructive Windows OLE file-drag sensing and expectation-animation loop to the approved V2.1 baseline and package it as `桌面宠物_文件拖动期待反馈.exe`.

**Architecture:** Keep OLE protocol handling, drag-state transitions, and Pillow-only transient visual decoration in focused modules. `PetWindow` owns exactly one drop target and supplies rendering/scheduling callbacks; the target only calls `QueryGetData` for `CF_HDROP`, never requests file contents and never performs a file operation. Windows registration is isolated behind an injectable adapter so Linux tests use fake `IDataObject` and registration objects.

**Tech Stack:** Python 3.11, ctypes/Win32 OLE, Pillow 11, Tk, pytest 8, PyInstaller 6, PowerShell, GitHub Actions.

## Global Constraints

- Start from current HEAD `c3b218df9dd0cfc84d96231701e771f0382388e1`; do not switch to an older branch.
- Do not change approved cat head, body, eyes, Alpha, head-neck deformation, eye following, or turn angles.
- Do not delete tests or update golden images; legacy visual regressions are recorded only.
- The feature never copies, moves, deletes, recycles, opens, uploads, reads, or modifies a dragged file and never changes hunger.
- Drag effects are transient runtime composition only; source assets remain byte-identical.
- Windows artifact and real-desktop visual acceptance remain separate pending gates.
