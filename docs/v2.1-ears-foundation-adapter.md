# V2.1-EARS 公共基础接入清单

当前分支没有 PR5 公共基础提交，因此本文件记录必须由总控完成的唯一适配边界；PR #9 不自建 `ActivityCoordinator`、`InputRouter`、事件队列、Clock 或 StateStore。

## Feature adapter

```python
EarFeatureAdapter.start_approved(
    side: Literal["left", "right"],
    context: EarActionContext,  # action_id + state_version + cancel_token
) -> bool

EarFeatureAdapter.cancel_and_recover(context: EarActionContext) -> bool

display(side: EarSide, pose: EarPose) -> None
complete(context: EarActionContext, safe_recovery_complete: bool) -> None
```

公共 `ActivityCoordinator` 必须先按活动优先级和 `CriticalHungry`/InputGate 状态批准，再调用 `start_approved`。完成回调必须由公共层复核动画 ID、状态版本、取消令牌及当前 Activity；高优先级中断调用 `cancel_and_recover`，收到安全恢复完成后才释放活动锁。

## InputRouter 所需调用

1. 按下时用 `PetWindow._point_in_ear_region()` 记录猫自身左/右耳候选，不启动动画。
2. 移动超过 `system_drag_threshold()` 返回的当前 DPI 系统阈值后，只路由 `DragPreview`。
3. 松开时仅当仍为同一耳区且没有进入拖动，向 `ActivityCoordinator` 请求对应耳活动。
4. 调试菜单的左右耳命令也必须进入同一个协调请求入口，不能直接绕过权限。

## 未完成依赖与发布阻塞

- 缺少 PR5 的 `desktop_pet.activity_coordinator.ActivityCoordinator` 与 `desktop_pet.input_router.InputRouter`。
- 当前 `PetWindow._request_ear_action()` 是明确标注的临时直接接线点；总控接入公共基础时必须将其替换为协调请求，不得保留双重状态权威。
- `build_ears_candidate.ps1` 要求 `V21_FOUNDATION_COMMIT` 且验证上述两个公共导入；缺失时主动拒绝生成候选 EXE。
- 公共基础接入、回调四元核验和统一 Recovery 完成前，本分支不是可验收成品。
