# V2.1-EARS 公共基础 adapter（PR5 实际 API）

## 已接入调用签名

```python
services = create_application_services(BuildInfo.load_embedded())
services.runtime.post("input.ear", source="window", side="left" | "right")
token = services.runtime.coordinator.request_activity(
    Activity.EAR_ACTION,
    animation_id="ear:left" | "ear:right",
    timeout_seconds=2.0,
)
services.animation.play("ears", side, token)
services.animation.complete("ears", token, token.animation_id)
services.animation.recover("ears", token)
```

`PetWindow` 只负责把用户按下候选、DPI 拖动阈值、同耳松开确认转成
`input.ear`。唯一 `RuntimeContext` 队列消费事件，唯一
`ActivityCoordinator` 持有活动权威、版本、取消 ID 和动画 ID；
`EarFeatureAdapter` 仅采样/显示局部耳姿态及执行物理中性恢复。

## 命中与画面

- `EarHitMasks.from_frame()` 每次以当前合成帧 Alpha 和文本人工多边形相交。
- 多边形和耳根通过当前 compositor 的 `map_head_point()` 映射，因此头部平移、旋转、缩放和形变后重新落位，不从上一帧累计。
- 动画直接对当前真实合成纹理做耳根固定的连续局部逆向网格；ROI 边界与耳根变形权重归零，不清空原耳、不复制对侧耳、不绘制几何替代线。

## 活动与恢复

- 左右耳共用 `Activity.EAR_ACTION` 和 `ears` channel；同级新点击不重启、不排队。
- adapter 完成后进入 0.5 秒冷却；冷却期间 channel 拒绝播放并由协调器恢复逻辑活动。
- Critical health 禁止耳动作。DragPreview、ContextMenuOpen、SevereHungerAnimation、
  FeedConfirm、FeedAnimation、FeedProcessing、TransactionReview、ShuttingDown 等更高优先级活动阻止耳请求。
- 更高优先级抢占调用 channel recovery：取消 Tk timer、显示零角姿态、清除窗口 token；旧完成回调因 token 四字段不匹配不能覆盖新活动。

## 尚待平台验收

Windows Actions 仅打包并检查唯一 EXE、精确名称、大小和 SHA-256。原生 Alpha
命中、PerMonitorV2 拖动阈值、局部补洞接缝和动作观感仍由用户 Windows 实机验收；
Linux 静态/临时目录探针不等同于该验收。
