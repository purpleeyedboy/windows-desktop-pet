# V2.1 Groom runtime integration

The entrypoint creates one `ApplicationServices`, loads its recovered shared state, and passes both into `PetWindow`. The foundation source is the real local Git commit `e0eefbd97ab5eecce764a41a53dda164c7f16baf`; `groom-foundation-source.json` records hashes of the unchanged public modules and identifies feature-adapted files. This is source provenance, not a claim that a particular remote head passed Windows checks.

`main -> PetWindow -> input.groom queue -> ActivityCoordinator(GROOM) -> GroomFeatureAdapter -> RuntimeEyeSession -> GroomFramePlayer -> layered renderer` is connected. The former unused procedural `GroomFoundationPort` was replaced by this raster bridge.

The approved left clip retains all 12 original frames. The separate right clip supplies another 12 authored frames, with vacancy restoration under the raised paw. Both use the same 640×768 canvas, identical actual following-renderer neutral endpoints and 75 ms frame timing. Main loads both validated clips explicitly; automatic starts choose one side once per round. Neither the loader nor player mirrors or substitutes a missing clip. The legacy source IDs `left` and `right` mean the historical white/orange asset packs, not anatomical left/right; visible labels use paw color to avoid that ambiguity. Three entry frames, the six-frame lick cycle repeated 3–20 times, and three recovery frames produce at most 9.45 seconds of playback. The 12-second activity deadline covers that sequence. The player cannot start itself while sampling. Idle expiry and the debug command request the same activity token before starting.

The existing eye controller provides the only grooming pulse. Grooming stays in `following`; it does not use the body player's recenter/pause path. Every raster display checks current token ownership. Natural completion clears cached imagery and completes that same token once. Preemption, right-click, mouse-down/drag initiation, timeout and close stop the player and clear its overlay; stale completion cannot release a replacement token. The current coordinator rejects critical health and protects feed/review/shutdown activities from lower-priority menu requests.

Right-click → 调试 → 白色前爪舔手（3次） / 橘色前爪舔手（3次） provides separate acceptance entries. The callback is deferred until the menu has returned. No real file operation or reward is required to test grooming.

Shutdown updates only current window coordinates/size in the live shared state before committing. Backup recovery, journal recovery, migration and log rotation use the imported common services. `build-info.json` preserves the candidate's debug switch; the additional `build_identity.json` provides the common runtime's actual source-head and foundation identity.

Required focused gates run even with the legacy `-SkipTests` switch:

- `python tools/verify_groom_side_selection.py`: one player/idle timer, fixed side per round, missing/unknown side rejection.
- `python tools/verify_groom_foundation_runtime.py`: actual two-sided 12-frame player, serialized input, automatic/debug authorization, complete/preempt/stale/close paths and single eye pulse.
- `python tools/verify_groom_foundation_recovery.py`: isolated synthetic migration, backup, journal, redacted rotating log, current-state close preservation.
- `python tools/verify_graphic_animation_contract.py`: shared body/feature playback, protected menu priority and strict logical-frame anchor compatibility.

The Windows workflow launches the EXE under an isolated temporary profile, requires its exact visible Tk window title, and reads a readiness marker emitted by that live window. Both actual loaded clips must report 12 frames and different RGBA digests, both color-named debug targets must be mounted, and the actual source head must match the workflow. The runtime gate invokes the same menu-bound callbacks and verifies different authored pixels. Local gate success does not certify Windows visual acceptance, and this change does not claim that the historical full pytest suite passes. The accepted original art is unchanged; the right clip and its repair layers are separate assets. The output is `桌面宠物_双侧舔手与中断恢复.exe`.
