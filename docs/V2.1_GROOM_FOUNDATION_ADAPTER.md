# V2.1 Groom shared-foundation adapter contract

Status: **blocked pending PR5 foundation and reviewed local assets**. This document is an integration checklist, not evidence of a runnable feature.

## Required shared API

PR5 must provide one process-wide implementation of:

- monotonic clock and injectable production/test RNG;
- serialized event queue and `ActivityCoordinator` authorization for `Groom`;
- current activity, state version, animation ID, and cancellation token;
- `HungerService`/Health state (`Normal` is required; `Critical` rejects grooming);
- InputGate facts for drag sensing, menu, pending feed transaction, and higher-priority animation;
- explicit-interaction idle duration, excluding ordinary cursor passage and eye-follow target changes;
- recovery completion and deferred normal ear/forelimb click replay with a fresh permission check;
- debug-menu registration for cat-left/cat-right and fixed 3/20 demonstrations.

`GroomFeatureAdapter.start(GroomStartRequest)` accepts only a coordinator-authorized request. Every sample, stop, recovery, and completion is keyed by the exact `GroomRunIdentity(animation_id, state_version, cancellation_token)`; stale identities are inert. The adapter owns no AppState, event queue, clock, state store, or global mouse listener.

## Coordinator policy (GRM-001–019)

The shared coordinator—not this feature—must require `Idle`, `Health.Normal`, no drag/menu/feed transaction/higher action, and 60 seconds since the last explicit interaction. It then samples a fresh 90–300 second delay and rechecks all conditions at expiry. Any disqualification cancels rather than queues the attempt and restarts full qualification.

Normal ear/forelimb intent requests a cycle-boundary stop and is retained as the one permitted deferred intent. Drag sensing requests urgent recovery and must enter `DragPreview` within 150 ms. Health below 20% requests a cycle-boundary stop unless a higher-priority urgent cancellation wins. Shutdown discards the run without persistence.

## Runtime call chain still required

`main -> shared foundation construction -> PetWindow input adapters/debug menu -> serialized event queue -> ActivityCoordinator -> GroomFeatureAdapter -> approved asset compositor with current head-anchor map -> transparent renderer -> identity-checked completion -> Recovery`.

None of the required PR5 classes exist in this branch as of this repair. Therefore `main.py`, `window.py`, and `eye_runtime.py` deliberately do not create a second coordinator or autonomous grooming loop.

## Reviewed asset dependency

The expected text manifest contract is recorded in `groom_asset_contract.json`. A real pack must contain original-texture cat-left/cat-right paw layers, paw-removal masks, vacancy-fill layers, mouth and tongue layers, anchors, hashes, and safe-frame data. No such reviewed pack is present, so the rejected geometric compositor has been removed and packaging is intentionally blocked.
